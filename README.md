# Car Shop 1.1.1 — автоматический локальный режим

Самостоятельное учебное приложение React + TypeScript + Vite для существующего REST API. Создание, редактирование, удаление, поиск по шести полям, сортировка и адаптивный интерфейс. Интерфейс на английском, как в задании; учебные пояснения на русском.

## Начните здесь

1. Установите Node.js 24 LTS (или Node >= 22.12). В Terminal на macOS откройте распакованную папку проекта: `cd `, затем перетащите папку в Terminal и нажмите Enter.
2. Выполните `npm ci`.
3. Для обычного запуска выполните `bash ./build-and-run.sh` (либо `npm run dev`). Приложение попробует API и автоматически включит локальное демо при сетевой ошибке, HTTP 5xx или отсутствии ответа за 8 секунд. Отдельный mock-процесс для этого не нужен.

Для отдельной практики с HTTP mock запустите `npm run mock` в первом Terminal. Во втором, в той же папке: `VITE_API_BASE_URL=http://127.0.0.1:4174/ npm run dev`. Откройте напечатанный адрес (обычно http://127.0.0.1:5173).
4. Добавьте машину, найдите её, измените, затем удалите с подтверждением. Локальные данные хранятся только в памяти; перезапуск mock восстанавливает два примера.
5. Прочитайте [условие без решения](docs/ASSIGNMENT.md), затем [полную пошаговую инструкцию и листинги](docs/MANUAL.md). Результаты и границы проверки: [VERIFICATION](docs/VERIFICATION.md).

## Подключение к учебному API

Без переменных приложение подключается к https://car-rest-service-carshop.2.rahtiapp.fi/. Для другого сервера выполните `cp .env.example .env`, измените `VITE_API_BASE_URL` и перезапустите Vite. `.env` не включается в архив. Переменные `VITE_*` публичны, в них нельзя хранить пароли.

Общий сервер используется другими студентами. Add/Edit/Delete меняют его данные; для упражнений и автотестов используйте mock. В комплекте нет вызова reset. При потере связи во время сохранения сначала обновите список: запрос мог успеть выполниться.

## Проверка

```sh
npm run typecheck
npm test
npm run build
npx playwright install chromium
npm run test:e2e
```

E2E автоматически запускает отдельные локальные серверы на 4174 и 4175. Перед тестом завершите свой `npm run mock`; тесты не переиспользуют чужой сервер. `npm run check:live` выполняет только GET и записывает обезличенный протокол. `npm run preview` показывает собранное приложение; для обычной работы используется `npm run dev`.

## Состав

- `src/` — всё приложение, типы, API, валидация и стили.
- `tests/` — контрактные и браузерные проверки.
- `scripts/` — локальный mock, GET-проверка, генерация полного руководства и упаковка.
- `docs/` — отдельное условие, инструкция, протокол и упражнения с отдельными решениями.
- `evidence/` — скриншоты и подтверждения проверенной версии.

Переносимый архив создаёт `npm run package` на Windows, используя штатный PowerShell. Запуск/сборка/тесты приложения переносимы на macOS. Общие скрипты координатора не входят в этот проект и не требуются для запуска.

## Подключение API при локальном запуске

Браузер на localhost/127.0.0.1 обращается к `/api/cars` своего приложения;
Vite dev и preview пересылают запрос в настоящий REST backend. Поэтому обычный
`bash ./build-and-run.sh` использует тот же путь, что и ручной запуск.
Прямой междоменный запрос из браузера не требуется; данные не подменяются.
`VITE_API_BASE_URL` по-прежнему задаёт настоящий сервер назначения.

После изменения `.env` остановите и снова запустите приложение. Для статического
хостинга на внешнем домене используется прямой HTTPS API; сервер Vite для него
не подразумевается. Тайм-аут загрузки списка в приложении — 8 секунд, изменения данных — 30 секунд; ENOTFOUND/ECONNREFUSED означают,
что до внешнего сервера не смог подключиться уже локальный Node-процесс.
Поддержка `AbortSignal.timeout` браузером не требуется.

## Как передать эту версию клиенту

Этот репозиторий содержит версию 1.1.1. Для обновления через download-and-run.sh выберите Car Shop и новую папку. Остановите старый запуск Ctrl+C и выполните `bash ./build-and-run.sh` в обновлённой копии. Перейдите по адресу, напечатанному Terminal (обычно http://127.0.0.1:4173 при preview).

При отказе API, HTTP 5xx или ожидании списка более 8 секунд автоматически появится жёлтый баннер **LOCAL DEMO** и две тестовые машины. Отдельно запускать npm run mock не нужно. Все последующие CRUD выполняются в памяти текущей вкладки; изменений общей базы и синхронизации из демо нет. Refresh остаётся в локальном режиме. Для повторной попытки подключения к API перезагрузите страницу: локальные изменения сбросятся.

Ошибки доступа 4xx и некорректный ответ не маскируются демо. Ошибка сохранения/удаления на настоящем сервере не повторяет операцию в mock: сначала обновите список. Интернет может требоваться для первоначального npm ci, даже если API недоступен.

В футере отображается **v1.1.1**. Номер автоматически берётся из package.json при сборке: для следующего выпуска он меняется в одном месте.
