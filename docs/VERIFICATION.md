# Car Shop — проверка и ограничения

Исходная версия проверена 14 октября 2026 на Windows: typecheck, production build,
16 unit и 5 браузерных тестов. CRUD проверялся только на локальном HTTP mock.
Публичная копия содержит исходники и тесты для самостоятельного повторения.
Локальные отчёты, пути компьютера исполнителя и прежние ZIP-квитанции не публикуются.

```sh
npm ci
npm run typecheck
npm test
npm run build
npx playwright install chromium
npm run test:e2e
```

Сквозная проверка загрузчика: `bash ./build-and-run.sh --smoke-test --no-open`.
Для ручного CRUD используйте `npm run mock` и во втором терминале
`VITE_API_BASE_URL=http://127.0.0.1:4174/ npm run dev`.
E2E самостоятельно запускает mock; порты 4174 и 4175 должны быть свободны.

| Требование | Готово | Как проверить | Ограничения |
|---|---|---|---|
| React/TypeScript/Vite и REST API | Да | typecheck, build, API tests | Для внешнего API нужна сеть |
| List/Add/Edit/Delete | Да | 16 unit и 5 E2E на локальном mock | Remote POST/PUT/DELETE не проверялись |
| Поиск, числовая сортировка, формы | Да | unit и E2E | Поиск по загруженной коллекции |
| Ошибки, загрузка, подтверждение удаления | Да | E2E HTTP failures и восстановление | Сетевые сбои моделируются |
| Адаптивный UI и управление фокусом | Да | E2E, viewport 390px | Отдельный screen reader аудит не выполнялся |
| Условие, руководство, практика и решения | Да | docs/ и полные листинги MANUAL | Фактический запуск на macOS не выполнялся |

Предыдущая read-only проверка общего API выполнила только GET /cars (HTTP 200).
Это не подтверждает текущие права записи на общий сервер. Mock хранит данные
в памяти; перезапуск восстанавливает примеры. Валюта backend не установлена.
Переменные VITE_* публичны и не предназначены для секретов.

## Проверка исправления локального API — 14 октября 2026

При запуске на localhost/127.0.0.1 frontend запрашивает `/api/cars` своего
приложения; Vite dev/preview передаёт запрос настоящему учебному REST API.
Проверка TLS сохраняется, mock автоматически не подставляется. Cookies других
локальных приложений не отправляются во внешний backend; Set-Cookie от него
не сохраняется на localhost. Внешний статический хостинг использует прямой API.

- Windows: 30/30 unit, production build/typecheck, 5/5 E2E на локальном HTTP mock.
- Ubuntu 22.04 WSL2: 30/30 unit и production build; настоящий Linux Chromium
  загрузил через production preview `/api/cars` 26 машин с учебного API.
- В Linux и Windows прямое обращение браузера к внешнему API было принудительно
  заблокировано; таблица всё равно загрузилась через локальный proxy, HTTP 200.
- Прежний прямой запрос также сработал в Windows и Linux; сбой на отдельном Mac
  в этих средах не повторился. Его точная сетевая причина не установлена.
- Добавлены AbortController и общий тайм-аут 30 секунд, охватывающий чтение JSON;
  браузеру больше не требуется AbortSignal.timeout. Ошибки proxy показывают код
  сетевого отказа; неправильный JSON и тайм-аут имеют отдельные сообщения.
- Remote POST/PUT/DELETE не выполнялись. Отображение реального списка не является
  подтверждением записи на общий backend. Фактический Mac по-прежнему не проверен.

| Пункт исправления | Проверка | Результат |
|---|---|---|
| Общий backend доступен | Настоящие GET из Windows и Linux | HTTP 200, 26 машин на дату проверки |
| Локальный frontend → proxy → REST API | Реальные Chromium, production preview | Таблица загружается без прямого browser API request |
| CRUD и ошибки интерфейса | 5 E2E, локальный mock | Успешно |
| URL, API-prefix, timeout и диагностика | 30 unit + build | Успешно |
| Работа на конкретном Mac | Не выполнялась | Не подтверждена |
